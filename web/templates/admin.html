  • Keep both (merge): Preserves the provider's version while saving your local edit as a distinct new event so nothing is lost.
  • Dismiss: Closes this conflict alert without altering event records.

Configuration Reload Boundaries

Settings that apply immediately versus parameters requiring an appliance service restart.

Setting / Parameter Boundary Effect & Lifecycle
Kiosk Preferences (Theme, Default View, Screen Schedule) Live Reload Stored in DB; applied instantly on page refresh or next view load
Calendar Visibility & Default Write Live Reload Takes effect on the very next event creation and sync cycle
Privacy Retention Rules Live Reload Read dynamically at each retention pass and cleanup execution
Google & Microsoft OAuth Client ID / Secret Live Reload Rebuilt in-process upon admin credential save
Admin Password Hash Live Reload Validated dynamically on each new login attempt
Server Host & Port (server.host, server.port) Restart Required TCP socket bound at daemon startup; requires systemctl restart familyboard
TLS Certificate & Key (server.tls_cert_file) Restart Required Loaded during HTTPS listener initialization; requires restart
Database Path & Connection Pools (database.path) Restart Required SQLite file lock and pool size initialized at process startup
Session Secret (security.session_secret) Restart Required Signing key bound at startup; changing invalidates all active sessions
Appliance Timezone (server.timezone) Restart Required Cached by internal clock and scheduling services at startup

Supported Upgrade Procedure: Every release upgrade executes preflight validation, downloads verified checksums, takes an automatic SQLite backup, runs forward schema migrations, and confirms readiness via /health/ready before completing.

To trigger or verify updates from the host appliance console:

sudo /opt/familyboard/bin/familyboardctl backup create
sudo /opt/familyboard/deploy/pi/update.sh

Emergency Rollback: If an update encounters host incompatibility, restore the pre-upgrade snapshot:

sudo /opt/familyboard/bin/familyboardctl backup restore <path-to-backup.db>
sudo systemctl restart familyboard
